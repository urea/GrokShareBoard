# 動画結合ブラウザツール実装 (2026/07/13)

## 決定

GrokShareBoard 配下の `/tools/video-join` に、インストール不要・サーバー処理不要の動画結合ページを追加した。

- 利用者が Grok 投稿ページから MP4 を自分の PC へ保存する。
- 保存した MP4 をブラウザへドラッグ＆ドロップ、またはファイル選択する。
- FFmpeg WebAssembly が利用者ブラウザの一時メモリ内で入力順に結合する。
- 完成 MP4 を日時付きファイル名で利用者が保存する。
- 動画、Grok URL、完成 MP4 は Supabase、GrokShareBoard サーバー、第三者ストレージへ送信しない。

処理サーバー、Vercel Functions、動画用オブジェクトストレージは追加していない。既存の Next.js static export / GitHub Pages 構成を維持する。

## 実装場所

| 対象 | 場所 | 役割 |
| --- | --- | --- |
| ルート | `_App/src/app/tools/video-join/page.tsx` | 静的ページとメタデータ |
| 操作画面 | `_App/src/app/tools/video-join/VideoJoinTool.tsx` | URLチェックリスト、ファイル選択、結合、ダウンロード |
| 本体導線 | `_App/src/app/page.tsx` | ヘッダー・フッターの「動画結合」リンク |
| 依存関係 | `_App/package.json` | `@ffmpeg/ffmpeg`、`@ffmpeg/util` |

## 利用体験

1. GrokShareBoard のヘッダーまたはフッターから「動画結合」へ移動する。
2. Grok 投稿 URL をドロップ、または複数貼り付ける。URLごとに公開動画をプレビューするカードを作る。
3. カードをドラッグ、または上下ボタンで並び替えて結合順を決める。
4. 各カードの「動画を保存」を右クリックし、「名前を付けてリンク先を保存」でMP4を保存する。WindowsではAlt＋クリック、スマートフォンでは長押しも案内する。通常の左クリックでは動画を開いて確認できる。
5. 保存したMP4をまとめて選択する。ファイル名に含まれるUUIDでカードへ自動割り当てし、同じUUIDを再選択した場合は後のファイルで上書きする。`UUID (1).mp4`のような重複名にも対応する。
6. 「動画を結合する」を押す。初回のみ固定バージョンの FFmpeg core 約32MBを CDN から読み込む。
7. 同形式なら再エンコードなしで高速結合する。解像度または音声有無が違う、あるいは高速結合に失敗した場合は互換変換へ移る。
8. 「完成MP4を保存」から `grok-joined-YYYYMMDD-HHMMSS.mp4` をダウンロードする。
9. 「このセッションを消去」でブラウザ内の出力 URL、FFmpeg worker、選択状態を解放する。

入力済みの Grok URL は `sessionStorage` に保存し、Fast Refresh やページ再読み込み後も同じタブ内で復元する。「このセッションを消去」を押すと削除する。ブラウザの安全制約により、選択済み MP4 は再読み込み後に再選択が必要。

## 初期制限

| 項目 | 値 |
| --- | --- |
| 入力形式 | MP4 のみ |
| 入力本数 | 2〜10本 |
| 合計入力容量 | 100MBまで |
| 出力 | MP4 |
| 高速結合 | 元ストリームをコピーし、画質・音質を変更しない |
| 互換変換 | 先頭動画の解像度へ scale / pad、30fps、H.264、AAC 48kHz stereo |
| 音声欠落への対応 | 一部の動画だけ音声がない場合は、その区間へ無音音声を補う |
| 推奨環境 | PC版 Chrome / Edge。短尺動画向け |

WebAssembly の一時ファイルシステムへ入力と出力を置くため、入力容量とほぼ同量だけでなく、処理中のコピーや互換変換用ファイルのメモリも必要になる。初期上限は WebAssembly の理論限界ではなく、実用時のブラウザ安定性を優先して100MBとした。

## FFmpeg の読み込み

- `@ffmpeg/ffmpeg` と `@ffmpeg/util` のラッパーはアプリ依存関係として固定する。
- FFmpeg core は `@ffmpeg/core@0.12.10` の単一スレッド版を、利用者が結合を実行した時だけ遅延読み込みする。
- core URL はバージョンを固定し、動画ではなく処理エンジンだけを CDN から取得する。
- マルチスレッド版は SharedArrayBuffer 用ヘッダーとメモリ消費が増えるため、GitHub Pages の初期版では使用しない。

## 検証結果

### 高速結合

- 320x240、H.264/AAC、約1秒のダミー MP4 を2本使用。
- ブラウザから完成 MP4 をダウンロードできた。
- `ffprobe` 結果: duration `2.023220` 秒、video `h264`、audio `aac`、320x240。
- 画面表示: 「高速結合・再エンコードなし」。

### 互換変換

- 1本目: 320x240、H.264/AAC。
- 2本目: 640x360、H.264、音声なし。
- 解像度と音声有無の差を検知し、両方を320x240・30fps・H.264/AACへ揃えてから結合できた。
- `ffprobe` 結果: duration `2.024333` 秒、video `h264`、audio `aac` 48kHz stereo、320x240。
- 画面表示: 「互換MP4へ変換して結合」。

### ビルド・表示

- `npx tsc --noEmit`: 成功。
- 新規ページを対象にした ESLint: エラーなし。
- `npm run build`: `/tools/video-join` を静的ページとして生成成功。
- Playwright: デスクトップ・390px幅のモバイル表示、GrokShareBoardからの遷移、ファイル追加、結合、ダウンロードを確認。

## 残る注意点

- xAI動画は別オリジンのためサイト内JavaScriptからBlob取得できない。カードから動画を開き、利用者がブラウザのダウンロード操作でMP4を保存する必要がある。
- 元 MP4 は利用者が保存したフォルダに残る。ブラウザから利用者ファイルを勝手に削除しない。
- 長尺・大容量・モバイル端末ではメモリ不足や長時間処理になる可能性がある。
- `npm run lint` 全体実行を妨げていた既存の `_App/src/app/user/page.tsx` の不要な同期 `setState` も削除し、全体Lintをエラーなしにした。既存コード由来の警告は残る。
