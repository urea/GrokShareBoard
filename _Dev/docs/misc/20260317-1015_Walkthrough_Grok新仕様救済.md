# Walkthrough: Grok新仕様への画像救済対応 (v1.7.0)

## 概要
Grokの画像/動画配信仕様が `imagine-public.x.ai` から `assets.grok.com` へ移行しつつあり、従来のUUIDベースのURL予測ロジックが一部のURL（特に最新の投稿）で機能しなくなっていた。これに対し、UUIDのみで画像を確実に特定できる「画像プロキシURL (?v=3)」方式を導入し、掲示板としての視認性を復旧させた。

## 実施内容

### 1. 調査と分析
- **原因**: 新ドメイン `assets.grok.com` ではパスに推測不能な `user_id` が含まれるようになった。
- **発見**: `https://grok.com/imagine/post/[UUID]/image?v=3` というエンドポイントが、Grok公式のメタタグ (`og:image`) で使用されており、UUIDのみでアクセス可能であることを特定。

### 2. コード修正 (`_App/src/components/ShareInput.tsx`)
- **フォールバックの強化**: `img` タグの `onError` チェーンの最終段に `?v=3` URLを追加。
- **DB保存ロジックの修正**: `handleShare` / `handleUpdate` において、画像読み込みに失敗している場合は、このプロキシURLを `image_url` としてDBに保存するように変更。
- **リトライの継続**: 旧仕様（Legacy）のURLが有効なパターンも存在するため、従来の予測（`.jpg`, `.png` 等）を試した後にプロキシURLへ到達する「多段構え」のレジリエンスを維持。

### 3. ドキュメント整備
- `_Dev/docs/misc/2026.03.17-07.45_Grok解析ロジック現状調査.md`: 解析結果と今回の暫定対処方針を記録。
- `CHANGELOG.md`: バージョン 1.7.0 として変更内容を明記。

## 動作確認の論理的担保
- **旧仕様URL**: 従来通り `imagine-public.x.ai` から画像を取得（変更なし）。
- **新仕様URL（b40441dd...等）**: 従来の予測が404エラーを返し、最終的に `?v=3` プロキシに切り替わり、画像が表示されることをロジック上で確認。
- **動画の扱い**: 動画URLの特定は新仕様では不可（ページ解析が必要）だが、画像が表示されることで「画像をクリックして本家で動画を視聴する」という基本動線が確保された。
