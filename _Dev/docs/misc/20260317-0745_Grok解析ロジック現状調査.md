# Grok解析ロジック 現状調査レポート (2026/03/17)

## 概要
Grok Share Board における「Load」ボタン実行時の解析ロジック（URLパースおよびリソース抽出）の現状仕様をまとめる。
Grok（x.ai）側の仕様変更が発生した際、どの部分に影響が出るかを特定するための資料とする。

## 1. 解析のトリガーとフロー
解析は `_App/src/components/ShareInput.tsx` の `handleAnalyze` 関数にて実行される。

1. **ユーザー入力**: `https://grok.com/imagine/post/[UUID]` 形式のURLを受け取る。
2. **UUID抽出**: URLから正規表現を用いてUUIDを切り出す。
3. **リソースURLの構築**: 抽出したUUIDを、決め打ちのCDNベースURLに当て嵌める。
4. **プレビュー表示**: 構築したURLを `img` または `video` タグの `src` にセットする。

## 2. 【2026/03/17 追記】最新の配信仕様と混在状態

調査の結果、Grok側の配信仕様は現在「新旧混在」かつ「投稿形式によって難易度が異なる」不安定な状態にあることが判明した。

### 2.1. 配信パターンの分類

| パターン | 特徴 | 解析の可否 (現状ロジック) | 推奨される新特定法 |
| :--- | :--- | :--- | :--- |
| **旧仕様 (Legacy)** | `imagine-public.x.ai` ドメインで配信。 | **可能** | 継続利用 |
| **新仕様 (Modern)** | `assets.grok.com` ドメイン。パスに `user_id` を含む。 | **不可** (予測不能) | スクレイピングによる `og:video` 抽出 |
| **画像のみ (Stable)** | 画像生成のみ。 | **一部不可** | `.../post/[UUID]/image?v=3` の利用 |

### 2.2. 強力な新候補：画像プロキシURL
動画を含まない、あるいはプレビュー画像だけで良い場合、以下のURLが極めて安定して利用可能である。
- **URL**: `https://grok.com/imagine/post/[UUID]/image?v=3`
- **特徴**: UUIDのみで構築可能、かつGrok公式のメタタグ (`og:image`) で採用されている。配信サーバーの変更（assets.grok.comへの移行等）をGrok側で吸収してくれる。

### 2.3. 不安定さの要因 (動画URL)
動画リソースについては、以下の理由により「予測」が困難になっている。
- パス構造: `https://assets.grok.com/users/[user_uuid]/generated/[post_uuid]/generated_video.mp4`
- 問題点: `user_uuid` は外部から（URLのみからは）推測できない。

## 3. 具体的なロジック詳細 (既存)

### UUIDの抽出 (RegEx)
URLパースには以下の正規表現が使用されている。
```typescript
const uuidMatch = url.match(/post\/([a-f0-9-]{36})/);
```
- **前提**: URLのパス部分に `post/` が含まれ、その後に36文字のUUIDが続く必要がある。

### リソースURLの構築 (構造)
取得したUUIDに基づき、以下のURLを生成する。
- **Video URL**: `https://imagine-public.x.ai/imagine-public/share-videos/${uuid}.mp4`
- **Image URL (Thumbnail)**: `https://imagine-public.x.ai/imagine-public/share-videos/${uuid}_thumbnail.jpg`

### 画像の多段フォールバック
`img` タグの `onError` イベントにおいて、リソースの所在が変更されている可能性を考慮し、以下の順序でURLを差し替えて再試行するロジックを持つ。
1. `_thumbnail.jpg` (デフォルト)
2. `https://imagine-public.x.ai/imagine-public/share-images/${uuid}.jpg` (パスと拡張子の変更)
3. `https://imagine-public.x.ai/imagine-public/share-videos/${uuid}.png` (動画ディレクトリ内のPNG)
4. `https://imagine-public.x.ai/imagine-public/images/${uuid}.jpg` (別ディレクトリ)

## 4. 想定されるリスク（Grok側の変更点）
1. **URL構造の変更**: `/imagine/post/` 以外のURL形式になった場合。
2. **UUID体系の変更**: 36文字の標準UUID形式（ハイフン区切り）以外になった場合。
3. **CDNドメインの変更**: `assets.grok.com` への完全移行。
4. **ユーザーIDの必須化**: 動画URL取得において「生成者ID」がパスに含まれるようになったこと。

## 5. 解決に向けた検討材料
### 短期的対応 (Low Cost)
- `ShareInput.tsx` の画像フォールバックに `.../image?v=3` を追加する。これにより、画像のみの投稿や動画プレビュー画像については100%の復旧が見込める。

### 根本的対応 (High Cost)
- **サーバーサイド・スクレイピング**: 
  解析（Load）時にウェブページをフェッチし、`og:video` および `og:image` メタタグから直接URLを抽出する。
- **課題**: Grok側のボット対策（CookieやIP制限）を回避する必要がある。
もし構造的に予測不可能になった場合、以下の対応が必要になる。
- サーバーサイド（API Route）でのGrok公開ページのフェッチと、DOM解析（Open Graphタグの抽出）。
- ヘッドレスブラウザ等を用いた、レンダリング後DOMからのURL特定。
