# Grok Share Board

**Grok Share Board** は、xAIのGrokによって生成された画像や動画（Grok Imagine）を共有・閲覧・検索できるキュレーションプラットフォームです。
見やすいグリッドレイアウトを採用し、視覚的に楽しめるインターフェースを提供します。ユーザー登録不要・匿名で、誰でも手軽にGrokの作品を共有できます。

## 🚀 主な機能

- **Grok URL共有**: `https://grok.com/imagine/...` のリンクを貼り付けるだけの簡単投稿。
- **完全レスポンシブデザイン**: 
  - スマートフォンからワイドモニター（最大1920px）まで、あらゆるデバイスで快適に閲覧できるグリッドレイアウトを採用。
  - 画面幅をして最大限の一覧性を提供します。
- **スマートプレビュー & リトライ**:
  - Grok投稿APIから現在の実メディアURLを解決し、`assets.grok.com`を使う新形式と従来形式の両方を扱います。
  - Grok側で未公開の投稿は、サムネイル・動画・元プロンプトを外部から取得できない場合があります。
  - プレビュー未生成時は「GrokでシェアまたはXに投稿」→「再確認」の手順案内を表示し、公開化を確認できるまで新規投稿を止めます。
- **日英バイリンガル対応**: UIは日本語と英語の併記に対応しており、海外ユーザーも利用可能です。
- **強力な検索機能**: サーバーサイド検索により、過去の全投稿からプロンプトで検索可能。
- **Grok元プロンプトの自動取得**: GitHub Actionsにより、追加投稿の元プロンプトを定期的に取得してDBへ反映します。
- **便利機能**:
  - **Copy Button**: プロンプト全文をワンクリックでクリップボードにコピー。
  - **匿名利用**: ユーザーIDの表示を撤廃し、完全にコンテンツ中心の設計に。

## 📝 使い方

1. **投稿する**:
   - Grokで画像/動画を生成し、そのURLをコピーします。
   - Grok側で「シェア」または「Xに投稿」を押すと、外部から表示・取得できる公開状態になります。
   - サイト上部の入力欄にペーストし、"Load / 読み込み" をクリックします。
   - プレビューを確認し、"Share / 投稿する" で完了です。
   - ※もしプレビューが表示されない場合は、画面の案内に従ってGrok側で公開化操作を行い、再確認してください。公開化を確認できるまで投稿はできません。
2. **閲覧・活用する**:
   - トップページに最新の投稿がグリッド表示されます。
   - 画像をクリックするとGrokの元ページが開きます。
   - プロンプトをコピーして、自分の創作に役立てることができます。

## 💻 技術スタック (Tech Stack)

このプロジェクトは、サーバーレスかつ静的ホスティング可能な構成で設計されています。

- **Framework**: Next.js 15+ (App Router)
- **Styling**: Tailwind CSS v4
- **Database**: Supabase (PostgreSQL)
- **Deployment**: GitHub Pages (Static Export) / Vercel

### 開発・運用メモ
このプロジェクトは、Grokの生成物がユーザー操作により公開可能な状態へ切り替わる仕様や、CORS制限、メディア保存先の変更を、VercelのメディアURL解決APIとクライアント側フォールバックで扱っています。

### Grok元プロンプトの定期取得

`.github/workflows/fetch-grok-prompts.yml` が1時間ごとに実行され、`posts.prompt_fetch_status` が `pending` または `failed` の投稿を対象にGrok側APIから元プロンプトを取得します。従来のMedia Post APIでプロンプトが空になるV2作品は、公開Asset APIの`mediaGenInput`へフォールバックし、`inputAssets`から元画像・上位作品も追跡します。`access_denied` はGrok側で公開化されていない可能性が高いため、通常の再取得対象から外します。ユーザーがGrok側で「シェア」または「Xに投稿」を押した後、詳細画面の「公開化済み・再取得を依頼」ボタンで `pending` に戻すことで、次回の自動取得対象になります。`no_prompt`、`source_missing` も終端ステータスとして通常の再取得対象から外しますが、Grok側の仕様移行時は手動ワークフローの`retry_no_prompt`で一括再確認できます。

このワークフローにはGitHub repository secret `DATABASE_URL` が必要です。Actionsログにプロンプト本文は出力せず、取得件数・HTTPステータス・本文長・ハッシュのみを記録します。
